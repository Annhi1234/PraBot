# PraBot

Легкий Discord-бот, натхненний [probot.io](https://probot.io/), з урізаним функціоналом.

**Created by A and I studio**

## Команди

Усе зібрано в одну команду `/prabot` з підкомандами — зручно шукати в списку команд Discord, а `/prabot help` одразу показує їх усі прямо в Discord.

**Привітання та вихід**
- `/prabot welcome-text текст:<текст>` — задає текст привітання. `{user}` замінюється на згадку нового учасника.
- `/prabot welcome-channel канал:<#канал>` — обирає канал для привітань і повідомлень про вихід.
- `/prabot welcome-off` — вимикає привітання.
- `/prabot leave-message текст:<текст>` — задає текст повідомлення, коли учасник виходить із сервера (в той самий канал, що й привітання). `{user}` тут — просто тег на кшталт `Ім'я#0001`, без пінгу (учасник уже вийшов).
- `/prabot leave-off` — вимикає повідомлення про вихід.

**Авто-роль**
- `/prabot autorole роль:<@роль>` — обирає роль, яка автоматично видається кожному новому учаснику.
- `/prabot autorole-off` — вимикає авто-видачу ролі.

**Журнал дій (логи)**
- `/prabot logs-channel канал:<#канал>` — обирає канал, куди PraBot дублює журнал дій: видані/зняті попередження (warn/clearwarnings), бани, кіки, мути й розмути (timeout/untimeout), зміни налаштувань (текст/канал привітання, авто-роль, сам канал логів), а також вхід і вихід учасників.
- `/prabot logs-off` — вимикає весь журнал дій одразу.
- `/prabot logs-toggle подія:<тип> увімкнено:<true/false>` — вмикає чи вимикає окремо взятий тип подій, не чіпаючи решту. Наприклад, `/prabot logs-toggle подія:Вхід_учасників увімкнено:false` прибере записи про вхід/вихід із журналу, лишивши бани/кіки/попередження увімкненими. Доступні типи: попередження, зняття попереджень, кіки, бани, мути, розмути, очищення повідомлень, зміни налаштувань, вхід учасників, вихід учасників.

Дизайн зроблено так, щоб не змішувати «вимкнути журнал повністю» (`logs-off`) і «прибрати конкретний тип шуму» (`logs-toggle`) — типові налаштування, зроблені через `logs-toggle`, зберігаються навіть після повторного `logs-channel`, поки їх явно не змінити знову.

**Модерація**
- `/prabot kick юзер:<@юзер> причина:<текст>` — кікає учасника.
- `/prabot ban юзер:<@юзер> причина:<текст> видалити-дні:<0-7>` — банить (можна одразу видалити недавні повідомлення).
- `/prabot timeout юзер:<@юзер> хвилини:<число> причина:<текст>` — видає таймаут (mute).
- `/prabot untimeout юзер:<@юзер>` — знімає таймаут.
- `/prabot warn юзер:<@юзер> причина:<текст>` — видає попередження (зберігається на сервері).
- `/prabot warnings юзер:<@юзер>` — показує всі попередження учасника.
- `/prabot clearwarnings юзер:<@юзер>` — очищує попередження учасника.
- `/prabot clear кількість:<1-100>` — видаляє останні N повідомлень у поточному каналі.

**Інформація**
- `/prabot stats` — памʼять (процесу і пристрою), пінг, час роботи.
- `/prabot serverinfo` — інформація про сервер.
- `/prabot userinfo юзер:<@юзер>` — інформація про учасника (за замовчуванням — про тебе).
- `/prabot settings` — показує поточні налаштування.
- `/prabot help` — список усіх команд прямо в Discord.

**Журнал дій** (`/prabot logs-channel`) тепер, крім модерації (варни/бани/кіки/мути) і входу/виходу учасників, пише і зміни, зроблені напряму в Discord (не через бота): створення/видалення/редагування ролей, каналів і зміни самого сервера (назва, іконка тощо), разом з тим, хто саме це зробив (якщо в бота є право "View Audit Log"). Кожен тип події можна вимкнути окремо через `/prabot logs-toggle`.

Усі підкоманди доступні тільки адміністраторам сервера (обмеження на рівні самої команди в Discord — окремо нічого налаштовувати не треба, але можна змінити в Server Settings → Integrations → PraBot, якщо захочеш дати доступ ще комусь — наприклад, дозволити модераторам користуватись лише командами модерації).

**Права бота.** Для модераційних команд боту потрібні відповідні права на сервері (Kick Members, Ban Members, Moderate Members, Manage Messages, Manage Roles — див. Крок 1 нижче). Якщо якогось права не вистачає, бот прямо про це скаже в ephemeral-відповіді, а не мовчки нічого не зробить. Для журналу змін ролей/каналів/сервера (хто саме що змінив) додатково бажане право **View Audit Log** — без нього бот все одно запише сам факт зміни, просто без "ким".

Налаштування та попередження зберігаються локально у файлі `settings.json` (створюється автоматично), без бази даних.

## Крок 1. Створення застосунку бота

1. Йди на https://discord.com/developers/applications → New Application → назви `PraBot`.
2. У розділі **Bot**: увімкни `Server Members Intent` (важливо — без нього бот не побачить нових учасників!) і натисни Reset Token — скопіюй токен.
3. У розділі **General Information**: там же можна вписати "Created by A and I studio" у полі Description.
4. Аватарку можна встановити двома способами:
   - Вручну: Developer Portal → General Information → перетягнути `assets/avatar.png`.
   - Або командою (коли `.env` вже заповнений): `npm run set-avatar`. Не запускай цю команду часто — Discord дозволяє міняти аватар не частіше ~2 разів на годину.
5. У розділі **OAuth2 → URL Generator**: обери scope `bot` та `applications.commands`, з прав — `Manage Roles`, `Moderate Members`, `Kick Members`, `Ban Members`, `Manage Messages`, `Send Messages`, `View Channels`, `Embed Links` (для гарних карток у журналі дій). Якщо якесь право не потрібне (наприклад, не плануєш банити нікого) — можна не давати, бот просто скаже про це у відповідній команді, а не зламається. Скопіюй згенероване посилання і запроси бота на свій сервер.
6. Роль бота на сервері (Server Settings → Roles) підніми **вище** за роль, яку він має видавати автоматично — інакше `/prabot autorole` сам це поясненню відмовить, а не мовчки зламається.

## Крок 2. Налаштування проєкту

Скопіюй `.env.example` в `.env` і заповни:
- `DISCORD_TOKEN` — токен з Кроку 1.
- `CLIENT_ID` — Application ID (там же, в General Information).
- `GUILD_ID` — ID твого сервера (увімкни Developer Mode в Discord → ПКМ по серверу → Copy Server ID).

**Важливо:** `GUILD_ID` тепер потрібен не тільки для `npm run deploy`, а й самому боту — він **сам реєструє слеш-команди при кожному запуску**, тому окремо запускати `npm run deploy` зазвичай не треба. Якщо в `.env` немає `GUILD_ID`, бот запуститься, але команди не зʼявляться в Discord — про це буде чітке попередження в консолі.

## Крок 3. Запуск на телефоні (Termux)

```bash
pkg update && pkg upgrade
pkg install nodejs git

cd PraBot
npm install
```

Реєструвати команди окремо (`npm run deploy`) більше не обовʼязково — бот робить це сам при старті. Скрипт лишився як допоміжний інструмент для діагностики (наприклад, щоб перевірити, що `.env` заповнений правильно, не запускаючи весь бот).

**Рекомендований спосіб запуску — через pm2**, бо він сам піднімає бота, якщо той впаде, і сам стежить за памʼяттю:

```bash
npm install -g pm2
npm run pm2:start
pm2 save            # щоб pm2 запамʼятав бота між сесіями Termux
```

Корисні команди:
```bash
npm run pm2:logs      # дивитись логи в реальному часі
npm run pm2:restart   # перезапустити вручну
npm run pm2:stop      # зупинити
```

Альтернатива без pm2 (простіше, але без авто-перезапуску при падінні):
```bash
pkg install tmux
tmux new -s prabot
npm start
# Ctrl+B, потім D — щоб "відʼєднатись", бот продовжить працювати у фоні
# повернутись: tmux attach -t prabot
```

## Крок 4. Запуск на звичайному ПК/сервері

Те саме, без Termux-специфіки — `npm install`, `npm run deploy`, далі `npm start` або `npm run pm2:start`.

## Лог-файли (якщо щось не працює)

Все, що бот виводить у консоль, дублюється у файли — зручно, коли з телефона важко скопіювати текст із самого терміналу:

- **`logs/prabot.log`** — повний лог (інформаційні повідомлення, попередження, помилки).
- **`logs/error.log`** — тільки помилки, окремо. Це перший файл, який варто відкрити, якщо щось не працює — він короткий і одразу показує суть проблеми.

Файли можна відкрити будь-яким текстовим редактором (навіть у Termux: `cat logs/error.log` або `nano logs/error.log`), скопіювати вміст і, наприклад, надіслати для діагностики.

Логи автоматично ротуються — коли файл переростає 5 МБ, старий перейменовується в `.1`, `.2`, `.3` (зберігаються 3 останні), і не забивають памʼять телефона нескінченно.

## Якщо команди не підказуються в Discord (не зʼявляються при вводі `/`)

Бот тепер **сам реєструє команди при кожному запуску** — це прибирає найчастішу причину проблеми (забутий `npm run deploy`). Якщо після цього команди все одно не показуються, перевір по порядку:

1. **Подивись у `logs/prabot.log` (або в консоль) при старті бота.** Там завжди буде видно: скільки серверів бачить бот і чи серед них є той, що вказаний у `GUILD_ID`. Якщо бот бачить 0 серверів або `GUILD_ID` не збігається з жодним із них — це і є причина, і повідомлення прямо про це скаже.
2. **`GUILD_ID` в `.env`** — має бути ID саме того сервера, де ти шукаєш команди (ПКМ по іконці сервера → Copy Server ID, попередньо увімкнувши Developer Mode в налаштуваннях Discord).
3. **Scope при запрошенні бота** — посилання-запрошення з Кроку 1 мусить містити і `bot`, і `applications.commands`. Якщо запрошував без другого — перезапроси бота за новим посиланням.
4. **Кеш клієнта Discord** — після реєстрації команд десктопний/мобільний клієнт Discord іноді кешує старий список. Перезапусти застосунок Discord (`Ctrl+R` у браузерній версії) або вийди й зайди на сервер.
5. **Права на сервері** — команда доступна тільки адміністраторам (`setDefaultMemberPermissions(Administrator)`). Якщо тестуєш акаунтом без прав адміністратора на цьому сервері — команда і не мусить показуватись, це очікувано, а не баг.

Якщо після всього цього все ще не працює — запусти `npm run deploy` вручну окремо від бота: він виведе детальнішу діагностику (звірить CLIENT_ID з токеном, покаже точний код помилки 401/403/404).

## Чому бот не повинен падати

- Всі мережеві та Discord API помилки логуються, а не валять процес (`unhandledRejection`, `uncaughtException`, `client.on('error')` — усе перехоплено).
- Запис налаштувань на диск атомарний (через тимчасовий файл + перейменування) — навіть якщо процес вб'ють просто посеред запису, `settings.json` не побʼється.
- Якщо `settings.json` все ж пошкодиться (наприклад, після відключення живлення телефона) — бот не впаде, а стартує з чистими налаштуваннями і збереже биту версію файлу поруч (`settings.json.broken-...`) для ручного відновлення.
- Битий файл однієї команди не валить весь бот при старті — просто пропускається з попередженням у консолі.
- `ecosystem.config.js` для pm2 сам перезапускає процес при падінні та має ліміт памʼяті (150 МБ) як страховку.
- Текст привітання не може випадково запінгати `@everyone`/`@here`/ролі — дозволено пінгнути тільки самого нового учасника.
- Втрата інтернету на телефоні (типова ситуація) не вбиває бота — discord.js сам перепідключається, а перепідключення логується, щоб було видно що відбувається.
- Другий випадково запущений екземпляр бота (наприклад, і через pm2, і вручну) не стартує і не плутає Discord-сесію — є lock-файл (`.prabot.lock`), який це виявляє.
- Версії залежностей (`discord.js`, `dotenv`) зафіксовані точно в `package.json`, а не діапазоном — `npm install` через кілька місяців на телефоні не підтягне версію з breaking changes, яку я не тестував.

### Довготривала робота (тижні без перезапуску)

Якщо тримаєш бота через pm2 постійно ввімкненим, варто раз налаштувати ротацію логів, щоб вони не забили памʼять телефона:

```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 10M
pm2 set pm2-logrotate:retain 3
```

## Оптимізація памʼяті

За замовчуванням discord.js кешує майже все — повідомлення, реакції, voice-стани, запрошення, стікери тощо. PraBot з цього нічого не використовує, тому весь зайвий кеш вимкнено в `index.js` (`makeCache`). Кеш учасників сервера теж обмежено до мінімуму — бот отримує учасника напряму з події входу і робить точковий `fetch()` для `/prabot untimeout`, тримати в памʼяті всіх учасників сервера не треба.

Завдяки цьому бот стабільно тримається в межах ~40–70 МБ оперативної памʼяті навіть на слабкому телефоні. Нові команди (модерація, попередження, інформація) цього не міняють: попередження — це лише невеликий JSON у `settings.json`, а `/prabot clear` видаляє повідомлення по ID без їх кешування (`MessageManager` все ще вимкнений).

## Структура проєкту

```
PraBot/
├── assets/
│   └── avatar.png        (аватарка бота)
├── commands/
│   └── prabot.js         (усі підкоманди в одному місці)
├── utils/
│   ├── storage.js
│   ├── loadCommands.js
│   └── logger.js          (пише логи і в консоль, і у файли)
├── logs/                   (створюється автоматично)
│   ├── prabot.log
│   └── error.log
├── index.js               (сам реєструє команди при старті)
├── deploy-commands.js      (опційно — ручна реєстрація з діагностикою)
├── set-avatar.js           (опційно — встановлює аватарку з assets/avatar.png)
├── ecosystem.config.js
├── package.json
├── .env.example
└── settings.json         (створюється автоматично)
```
